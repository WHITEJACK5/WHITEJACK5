# How the profile updates itself

Every graphic in the profile README is generated by a script in this folder and
committed back to the repository by GitHub Actions. There are no third-party
image services, so nothing breaks when an external widget goes down.

## What runs

| Workflow | Schedule | What it writes |
| :-- | :-- | :-- |
| `refresh-stats.yml` | every 3 hours (`0 */3 * * *`) | `stats.svg`, `streak.svg`, `langs.svg`, `year.svg` |
| `update-readme.yml` | every 3 hours (`0 */3 * * *`) | the table between `<!-- REPOS:START -->` and `<!-- REPOS:END -->` in `README.md` |

Both also expose `workflow_dispatch`, so they can be run on demand. Neither
triggers on `push`: they commit their own output, and a push trigger would make
them loop on their own commits.

## Data source

`generate_stats.py` talks to the GitHub GraphQL API with the standard library
only. It sums `contributionsCollection` year by year (in half-year windows, so a
leap year never exceeds the API's one-year span limit) to get all-time commits,
pull requests, issues and reviews, and reads `restrictedContributionsCount` for
private contributions.

Repositories are always queried with `privacy: PUBLIC`, so the numbers are the
same whether the run uses a personal token or the workflow's default token.

## The optional `STATS_TOKEN` secret

Private contribution counts are only visible to a token that is allowed to see
them. Without one, that tile reports `0` while every public number stays
correct.

To include private contributions, add a repository secret named `STATS_TOKEN`
containing a personal access token with:

- `read:user` — profile, followers, contribution counts
- `repo` — private repository contributions

The workflows read it as:

```yaml
GITHUB_TOKEN: ${{ secrets.STATS_TOKEN || secrets.GITHUB_TOKEN }}
```

So the secret is optional: if it is absent, the default `GITHUB_TOKEN` is used
and the run still succeeds.

## Running it by hand

From the repository root:

```bash
GITHUB_TOKEN=<token> GH_LOGIN=<login> python3 scripts/generate_stats.py
GITHUB_TOKEN=<token> GH_LOGIN=<login> python3 scripts/update_repos.py
```

Or from the GitHub UI: **Actions** → `refresh stats` / `update readme repos` →
**Run workflow**. The job commits only when a generated file actually changed.

## Rebuilding the README

`scripts/fix_readme.py` is the source of truth for `README.md`. It preserves the
contents of the `<!-- REPOS:START -->` / `<!-- REPOS:END -->` block, so run it
before editing the README by hand:

```bash
python3 scripts/fix_readme.py
```

`scripts/render_adam.py` regenerates the header GIF from
`assets/creation-of-adam-source.jpg`.

## Optional extra cards

`profile.svg` (all-time tiles), `yearly.svg` (contributions per calendar year)
and `repos.svg` (recently pushed repositories) are implemented and tested, but
the README shows only the four core cards until a real run has produced
numbers. To emit and commit them again, set `EXTRA_CARDS=1` when running:

```bash
EXTRA_CARDS=1 GITHUB_TOKEN=<token> GH_LOGIN=<login> python3 scripts/generate_stats.py
```

Then reference the generated files in the GitHub Stats block of
`scripts/fix_readme.py`.
